Home 조언자 AI 서버 사용 설명서

온보딩에서 받은 프로필(언어·국가·성별·연령대)이나 사용자 질문을 보내면, 크롤링 DB에서 근거를 골라 근거 ID가 붙은 추천 문장을 돌려주는 서버입니다. 이 문서 하나로 호출 방법과 응답 읽는 법, 다른 PC에서 실행하는 방법을 모두 알 수 있습니다.

대상: 팀원 · 서버를 호출하는 Claude Code 서버: app.serve · 포트 8000 예시 실측: 2026-10-24

1한눈에 보기

요청 하나가 서버 안에서 거치는 길입니다. LLM은 마지막 단계(Haiku)에서만 씁니다.

요청질문 또는 프로필
/v1/chat/completions
/v1/responses
→
① Jev 판단무슨 주제인가(category)
어떤 콘텐츠인가(content_kind)
의료 관심(medical_intent)
→
② retrieveCrawling_DB에서 조건에 맞는 근거 최대 5건을 규칙으로 고름(LLM 없음)
→
③ Haiku 응답고른 근거만 써서 답하고 항목마다 [근거 ID]를 붙임

범위 밖 질문(주식·날씨 등)은 ①에서 바로 decline(정중한 거절)으로 가고 ②는 건너뜁니다.

무엇을 보내나

OpenAI 형식의 요청에 metadata.profile을 더합니다. 질문 없이 프로필만 보내면 Home 추천을 만듭니다.

무엇을 받나

OpenAI 형식의 응답입니다. 본문은 자연어이고, 추천 항목마다 [products/…] 같은 근거 ID, 출처 URL, 협찬 상태가 들어 있습니다.

지키는 원칙

성별·연령으로 피부나 의료 적합성을 판단하지 않습니다. 근거가 없으면 없다고 말합니다. 의료는 장소 안내만 합니다.

2API 목록

기본 주소는 http://localhost:8000입니다. 인증 헤더는 없습니다(로컬 개발 서버).

메서드경로하는 일언제 쓰나
GET/health서버 상태, 그래프 노드, 읽어 들인 근거 수서버가 떴는지 확인할 때
GET/v1/models사용 가능한 model 목록(현재 kbeauty-haiku)요청에 넣을 model 이름을 확인할 때
POST/v1/chat/completionsOpenAI Chat Completions 형식. 일반·스트리밍기본으로 이것을 쓰세요
POST/v1/responsesOpenAI Responses API 형식. 일반·스트리밍. 그래프는 위와 같음Responses 형식 클라이언트를 쓸 때
참고같은 라우터에 /v1/discovery·/v1/auth도 있습니다. 이것은 탐색 앱(app.discovery_server, 포트 8001) 담당이라 이 문서에서는 다루지 않습니다. 저장소 README.md를 보세요.

3IN — 보내는 데이터

무엇을 보내느냐에 따라 서버가 두 가지 모드로 동작합니다.

3-1. 모드는 이렇게 정해집니다

보낸 것모드서버가 하는 일
질문(마지막 user 메시지) 있음질문 모드질문으로 판단합니다. 프로필이 있으면 근거 고르기와 말투에 함께 씁니다.
질문 없음 + 프로필 있음Home 모드서버가 언어·국가만으로 "Home 추천 요청" 문장을 만들어 판단합니다. 온보딩 직후 Home 최상단용입니다.
둘 다 없음—400 오류

3-2. 프로필(profile) — 모두 선택 항목

키형식예어디에 쓰나
languageISO 639-1 (대소문자 무관, en-US → en)en, ja, zhJev 판단, 근거 점수, 응답 언어
countryISO 3166-1 2자리 (자동 대문자)US, JP, SGJev 판단, 근거 점수, "국가 근거 부족" 표시
gender자유 문자열female말투에만 사용
age_band자유 문자열20s말투에만 사용
성별·연령은 판단에 쓰지 않습니다Jev(판단 모델)에는 아예 전달되지 않고, 근거 고르기에도 쓰지 않습니다. Haiku가 말투를 맞출 때만 봅니다. 국가만으로 피부 타입이나 시술 적합성을 단정하지도 않습니다(기획안 §5-1).

프로필은 두 가지 방법 중 편한 쪽으로 보내면 됩니다.

방법 A — 객체(권장) 
"metadata": {
  "profile": {
    "language": "en", "country": "US",
    "gender": "female", "age_band": "20s"
  }
}
방법 B — 평탄한 문자열 키(OpenAI SDK 규격) 
"metadata": {
  "language": "en",
  "country": "JP"
}

3-3. POST /v1/chat/completions 본문

필드필수설명
model✅"kbeauty-haiku" (목록은 /v1/models)
messages배열. 마지막 메시지만 질문으로 씁니다. 마지막은 role: "user"여야 합니다. system 메시지는 무시합니다. content는 문자열 또는 [{"type":"text","text":"…"}]. Home 모드는 []
streamtrue면 SSE 스트리밍(기본 false)
metadata프로필(위 3-2)
그 밖temperature·max_tokens·stream_options 등은 받기만 하고 무시합니다

3-4. POST /v1/responses 본문

필드필수설명
model✅"kbeauty-haiku"
input문자열(질문) 또는 메시지 배열(마지막 user 메시지만 사용, 내용 파트 input_text 지원). 생략하면 Home 모드
streamtrue면 Responses 이벤트 스트림
metadata프로필. 응답의 metadata로 그대로 돌려줍니다
그 밖instructions·tools 등은 무시합니다
멀티턴기본은 꺼져 있습니다(요청마다 독립). envs/agent_config.yaml의 multi_turn.enabled: true로 켜면 요청 헤더 X-Thread-Id가 필수가 됩니다.

4OUT — 받는 데이터

응답 봉투(JSON 모양)는 OpenAI 형식과 같습니다. 이 서버만의 약속은 본문 텍스트 안에 있습니다.

4-1. 응답 봉투

chat/completions (일반) 
{
  "id": "chatcmpl-…",
  "object": "chat.completion",
  "created": 1792820904,
  "model": "kbeauty-haiku",
  "choices": [{
    "index": 0,
    "message": {"role": "assistant",
                "content": "← 본문"},
    "finish_reason": "stop"   // 또는 "length"
  }]
}
responses (일반) 
{
  "id": "resp_…",
  "object": "response",
  "created_at": 1792820912,
  "status": "completed",     // 또는 "incomplete"
  "model": "kbeauty-haiku",
  "output": [{
    "type": "message", "role": "assistant",
    "content": [{"type": "output_text",
                 "text": "← 본문",
                 "annotations": []}]
  }],
  "metadata": {"language": "en", "country": "JP"}
}
스트리밍순서
chat/completionsdata: {chat.completion.chunk} 여러 개 → 첫 chunk만 role 포함 → 마지막 chunk는 delta: {} + finish_reason → data: [DONE]
responsesresponse.created → response.output_item.added → response.content_part.added → response.output_text.delta(여러 개) → response.output_text.done → response.content_part.done → response.output_item.done → response.completed. 모든 이벤트에 1부터 늘어나는 sequence_number

4-2. 본문 읽는 법 — 이 서버의 약속

본문 속 표시뜻클라이언트가 할 일
[products/naver-blog-…]
[clinics/…] [videos/youtube-…]		근거 ID(concept ID). 이 응답이 실제로 고른 DB 항목정규식으로 뽑아 카드 UI와 연결합니다. 파일은 Crawling_DB/<ID>.md
Source: https://…원문 링크(블로그 글·영상)그대로 링크로 보여줍니다
Sponsored: yes / no (self-declared) / unknown협찬 표시. no는 작성자 자기 선언(예: 내돈내산)이고, unknown은 확인 못 함unknown을 "협찬 아님"으로 바꾸지 마세요
Unverified · outdated사람 검수 전(status: draft) · 신선도 만료(stale_after 지남)배지로 표시합니다
country evidence insufficient프로필 국가에 맞는다는 근거가 데이터에 없음"국가 근거 부족" 표시
"consult the clinic directly"의료 항목에 항상 붙는 고정 안내지우지 마세요(장소 안내만 하고 효과·적합성은 판단하지 않음)
"no matching evidence" / "broadened"조건에 맞는 근거 0건 / 콘텐츠 종류 조건을 넓혀서 찾음빈 상태 UI를 보여줍니다
근거 ID 뽑기(정규식) 
\[((?:products|clinics|videos)/[A-Za-z0-9_.\-]+)\]
문장은 매번 달라집니다본문은 LLM이 쓰므로 표현·순서가 호출마다 바뀝니다. 기계적으로 의존할 것은 근거 ID뿐입니다. 근거 ID는 항상 서버가 고른 목록 안에서만 나옵니다. 어떤 ID를 골랐는지는 서버 로그 [Retrieve] ✅ … ids=[…]에서 확인할 수 있습니다.

4-3. 근거 ID로 상세 정보 얻기

ID에 .md를 붙인 파일의 맨 위 YAML에 카드에 쓸 값이 다 들어 있습니다. 필드 설명은 Crawling_DB/README.md에 있습니다.

Crawling_DB/clinics/naver-blog-khshi001-224435086306.md
  title · description(스니펫) · resource(원문 URL) · category · content_kind · source_kind
  sponsored(+evidence) · foreigner_friendly(+evidence) · country_signals · language_signals
  status: draft · stale_after · sources[origin].author · last_modified(게시일)

4-4. 오류

오류는 항상 OpenAI 오류 형식 {"error": {"message", "type", "param", "code"}}입니다.

상태언제type / code
400질문도 프로필도 없음, 마지막 메시지가 user가 아님, 본문 형식 오류invalid_request_error
404없는 model 이름invalid_request_error / model_not_found
500Jev·Haiku 호출 실패 등. 스트리밍이어도 첫 토큰 전에 실패하면 SSE 대신 500 JSONserver_error

⑦ Python (표준 라이브러리만) — 근거 ID까지 뽑기

import json
import re
import urllib.request

BASE = "http://localhost:8000"
CONCEPT_ID = re.compile(r"\[((?:products|clinics|videos)/[A-Za-z0-9_.\-]+)\]")


def ask(profile: dict, question: str | None = None) -> dict:
    body = {
        "model": "kbeauty-haiku",
        "messages": [{"role": "user", "content": question}] if question else [],
        "metadata": {"profile": profile},
    }
    req = urllib.request.Request(
        f"{BASE}/v1/chat/completions",
        data=json.dumps(body).encode(),
        headers={"Content-Type": "application/json"},
    )
    with urllib.request.urlopen(req, timeout=120) as r:
        return json.load(r)


reply = ask({"language": "en", "country": "JP"}, "Any dermatology clinic in Gangnam for foreigners?")
text = reply["choices"][0]["message"]["content"]
print("finish_reason:", reply["choices"][0]["finish_reason"])
print("cited concept ids:", CONCEPT_ID.findall(text))
