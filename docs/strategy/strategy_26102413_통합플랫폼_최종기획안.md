# 통합 플랫폼 최종 기획안

> 근거 범위: 회의 요약은 2026-10-24 자동 전사 **12:51:03~13:07:47** 구간만 사용했다. 그 이전 논의는 이 문서의 합의로 넣지 않았다. 국가별 추천(5-1절)은 전사가 아니라 최신 사용자 추가 요구로 별도 반영했다.
> 전사의 화자 표시가 모두 같은 이름이라 발언자를 구분할 수 없다. 그래서 사람 대신 **역할**로 적는다.
> 이 문서가 바꾸는 것: [strategy_26102411_K뷰티_제품_구체화.md](strategy_26102411_K뷰티_제품_구체화.md)의 "K-의료 후순위"를 대체한다. 이전 문서는 이력으로 보존한다.

표기 규칙

- **[합의]** 전사에서 질문과 동의 응답이 확인된 것
- **[유력]** 명시적인 확정 없이 제안됐고, 반대 없이 논의가 그 방향으로 이어진 것. 최종 결정은 아님
- **[제안]** 화면·기능 아이디어. 구현이나 확정을 뜻하지 않음
- **[미정]** 결정 보류이거나 확인이 필요한 것
- **[확정 요구]** 전사가 아니라 사용자가 직접 추가한 확정 요구

## 1. 한 줄 방향

**한국을 찾는 외국인이 K-뷰티와 K-의료를 한곳에서 탐색하고, 근거를 보며 고른 뒤, 방문 경로와 일정까지 이어가는 통합 플랫폼. 추천은 사용자가 고른 국가와 개인 조건에 맞춥니다.**

1. **[합의] 뷰티와 의료로 수평 확장합니다.** 13:07:45에 "지금 수평 확장이고, 찬성하시나요?"라는 질문에 "네, 의료 방문부터 시작해서 뷰티까지"라는 응답이 있었습니다.
2. **[유력] 근거를 보여주는 추천(설명 가능한 AI)을 핵심으로 합니다.** 기존 서비스의 추천은 근거가 보이지 않는다는 문제의식에서, 리뷰와 영상 같은 근거를 함께 제시하자는 의견입니다(13:00:09).
3. **[유력] 랭킹 자체는 차별점이 아닙니다.** 떠오르는 제품·판매량·리뷰 기준 랭킹은 기존 서비스에 이미 있다는 발언이 있었습니다(12:56:49~12:57:09). 그래서 랭킹은 탐색 도구로 두고 차별점으로 내세우지 않습니다.

## 2. 고객과 문제

- **고객:** 한국을 방문해 뷰티 쇼핑과 의료 방문을 함께 고려하는 외국인.
- **[미정] 의료 세부 범위:** 피부과, 건강검진, 치과 중 어디까지 다룰지는 정하지 않았습니다.
- **전사 해석:** 13:02:59의 '의류' 발화는 문맥상 '의료'로 해석했습니다. 패션 확장에 합의한 것이 아닙니다.
  - 회의 발언 요지: "의료 관광객도 화장품을 소비할 것으로 예상된다"(13:02:59).
- **문제(회의 발언 요지):**
  1. 자기가 쓰던 제품과 비슷한 한국 제품을 한국인은 무엇을 쓰는지 비교하기 어렵습니다(12:51:54, 12:56:09).
  2. 의료 쪽 기존 서비스는 탐색·번역·추천은 하지만 여행 경로와 연결되지 않는다는 문제 제기가 있었습니다(13:00:09, 13:03:09).
- **주의:** 경쟁사 기능에 대한 발언은 회의 중 의견입니다. "경쟁사에 없다"는 문장을 발표에 그대로 쓰지 않습니다. 경쟁사 공식 기능은 별도 조사 링크로 확인한 범위에서만 씁니다.

## 3. 화면 구성 [제안]

### 3.1 Discover (탐색)

- 뷰티와 의료를 함께 탐색합니다(13:07:46).
- 뷰티 탐색은 기존 참고 화면의 미니멀한 구조를 유지하고, 정보량을 보강하는 방향입니다.
- **제품 랭킹 + 선택 제품의 세로 숏폼 + 상품 카드**로 구성합니다. 상품 카드에 광고·협찬 여부 표시가 필요하다는 발언이 있었습니다(13:03:19). 백엔드 판별이 안 되더라도 UI에는 표시 칸이 있어야 한다고 했습니다.
- **비교 후보:** 내가 쓰던 제품과 같은 카테고리에서 한국인이 많이 쓰는 대안을 보여줍니다(12:51:54~12:52:06).
- **Real 랭킹과 Sponsor 분리:**
  - 리얼 랭킹 탭과 스폰서 탭을 나눕니다.
  - 스폰서 탭은 "지금 홍보 중인 제품"을 별도로 보여줍니다(12:51:19, 13:07:45).
  - 스폰서 노출은 실제 순위와 섞지 않습니다.

### 3.2 카트·통화·가격 차이

- `+` 버튼으로 하단 카트나 패널에 담고 합계를 봅니다(12:52:15~12:52:36, 13:07:45).
- 거주국 통화로 환산한 금액을 보여주자는 제안이 있었습니다.
- 리얼 랭킹 제품과 스폰서·대안 제품의 가격을 나란히 보여주자는 제안도 있었습니다(13:07:45~13:07:46).
  - 서로 다른 제품의 가격 차이는 할인이 아닙니다. 할인은 같은 상품의 정가와 판매가 근거가 있을 때만 표시합니다.
  - 효과나 만족을 보장하는 문구로 쓰지 않습니다.

### 3.3 My Trip (내 여행)

- 방문하고 싶은 곳(뷰티·의료)을 추천받고, 경로를 자동으로 만들고, 일정까지 추천받는 화면입니다(13:05:29).
- 탐색만 원하면 Discover만 써도 됩니다.
- 의료 판단과 예약 확정은 의료기관이 합니다. 의료 판단을 자동화한다고 표현하지 않습니다.

- 참고 화면 https://kbeauty-proof-and-popularity.lovable.app/ 은 예은님이 참고한 화면입니다. 구현 정본 전체가 아닙니다.

## 5-1. 국가별 추천 (사용자 추가 확정 요구, 전사 외)

> 회의 전사가 아니라 사용자가 직접 추가한 확정 요구다(2026-10-24): "외국인 200만명을 다 대상으로 할 수 없으니 추천 서비스가 있으니깐. 각 나라별 추천도 적용이 돼야한다."

- **[확정 요구] 기능 정의:** 단순 번역이나 통화 변경이 아닙니다. 선택한 국가의 제품 맥락과 개인 입력(기존 사용 제품, 예산, 방문 목적 등)에 따라 후보와 추천 이유를 조정합니다.
- **금지 사항:**
  - 국가만으로 피부 타입, 시술 적합성, 개인 취향을 단정하지 않습니다.
  - 국가만 바꿨다고 무조건 순위를 흔드는 규칙을 만들지 않습니다.
- **[제안] 최소 입력:** 사용자가 직접 선택하고 수정하는 국가·언어·통화와 개인 조건입니다. 위치 자동 추정을 필수로 두지 않습니다.
- **데이터가 없을 때:** 임의의 국가 통계를 만들지 않습니다. 공통 근거 기반 추천과 "국가 근거 부족"을 구분해 표시합니다.
- 200만은 목표 고객 수나 TAM 확정값으로 쓰지 않습니다.
- **[미정]:** 먼저 공략할 국가와 데모 대상국. 입력·응답 형식 스키마는 구현 제안입니다.

## 7. 미정 항목 (임의 확정 금지)

1. 2장에 기술 워크플로우를 얼마나 넣을지
2. 수익 모델의 구체 구조(스폰서 과금 방식, 수수료, 의료 쪽 수익)와 의료 알선 관련 등록 요건
3. 의료 세부 범위(피부과·건강검진·치과)
4. 국가별 추천에서 먼저 공략할 국가와 데모 대상국
5. 광고·협찬 판별 방법과 정확도. 표시가 없다고 비협찬으로 단정하지 않음
6. 화해 등 외부 데이터의 사용 권리, 통화 환산에 쓸 환율 출처
7. 제품명. 참고 화면의 "bloom."은 확정이 아님
8. 백엔드 API 구조·DB·스키마
